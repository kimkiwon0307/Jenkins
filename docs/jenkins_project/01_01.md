# Jenkins 프로젝트 학습

## 1장 1교시 — CI/CD 개념과 Jenkins의 역할

### 1. CI/CD란?

**CI (Continuous Integration) — 지속적 통합**
- 개발자가 변경한 코드를 자주 통합하고 자동 검증하는 방식
- 코드 Checkout → Build → Test
- 코드 충돌 및 오류를 조기에 발견하는 것이 목적

**CD (Continuous Delivery) — 지속적 제공**
- 테스트를 통과한 결과물을 언제든 배포할 수 있도록 준비
- 운영 배포 시 수동 승인 가능

**CD (Continuous Deployment) — 지속적 배포**
- 테스트 및 검증 통과 후 운영 환경까지 자동 배포
- 별도의 수동 승인 없이 배포 진행

### 2. Jenkins란?

Jenkins는 빌드, 테스트, 배포 등의 작업을 자동화하는 오픈소스 자동화 서버이다.

**주요 역할**
- GitHub 소스 코드 가져오기
- Maven/Gradle을 통한 자동 빌드
- 자동 테스트 실행
- WAS 서버 자동 배포
- 빌드 및 배포 결과 확인
- 실패 시 배포 중단 및 설정된 복구 절차 실행

### 3. 수동 배포와 자동 배포 비교

| 구분 | 수동 배포 | Jenkins 자동 배포 |
|---|---|---|
| 소스 코드 | 담당자가 직접 가져옴 | 자동 Checkout |
| 빌드 | 직접 실행 | 자동 실행 |
| 테스트 | 직접 실행 | 자동 실행 |
| 배포 | 담당자가 직접 수행 | Pipeline을 통해 자동 수행 |
| 장점 | 단순한 환경에 적합 | 반복 작업 감소, 일관성 향상 |
| 단점 | 사람의 실수 가능성 | 초기 구축 및 유지관리 필요 |

### 4. Jenkins CI/CD 동작 흐름

```text
개발자
   │
   ▼
GitHub Push
   │
   ▼
Webhook
   │
   ▼
Jenkins Pipeline
   │
   ├── Checkout : 소스 코드 가져오기
   ├── Build    : JAR 파일 생성
   ├── Test     : 자동 테스트 실행
   ├── Deploy   : WAS 서버에 배포
   └── Verify   : 서비스 정상 작동 확인
   │
   ▼
Spring Boot 애플리케이션 운영
```

※ Build와 Test의 순서는 프로젝트 빌드 도구 및 Pipeline 설정에 따라 달라질 수 있다.

### 5. 장애 발생 시 대응

**① 자동 테스트 실패**
- 신규 버전 배포 중단
- 기존 정상 버전 유지
- 실패 로그 분석 및 코드 수정
- 재검증 후 배포

**② 신규 버전 배포 후 장애 발생**
- 헬스체크를 통해 장애 확인
- 필요 시 이전 정상 버전으로 롤백
- 로그 분석 후 원인 해결

**핵심:** 테스트 실패는 배포 차단, 배포 후 장애는 롤백을 고려한다.

### 6. Jenkins와 GitHub Actions 비교

| Jenkins | GitHub Actions |
|---|---|
| Jenkins 서버 직접 운영 가능 | GitHub 호스팅 실행 환경 제공 |
| Jenkinsfile 사용 | YAML 사용 |
| Controller/Agent 구조 | Runner 기반 실행 |
| 높은 구성 유연성 | GitHub 연동 편리 |
| 서버 운영 및 관리 필요 | 호스팅 방식은 관리 부담 적음 |

### 7. Jenkins 서버 점검 명령어

```bash
# Jenkins 서비스 실행 상태 확인
systemctl is-active jenkins

# Jenkins 서비스 상세 상태 확인
systemctl status jenkins

# Jenkins 기본 포트(8080) 확인
sudo ss -lntp | grep ':8080'
```

※ systemctl 명령어는 systemd 서비스로 설치한 Jenkins 기준이다.

### 8. 핵심 요약

1. **CI** = 코드 통합 및 자동 빌드·테스트
2. **Continuous Delivery** = 언제든 배포 가능한 상태 유지
3. **Continuous Deployment** = 검증 후 자동 배포
4. **Jenkins** = CI/CD 작업을 자동화하고 관리하는 서버
5. **Pipeline** = 빌드·테스트·배포 작업의 순서와 조건
6. **안전한 배포** = 테스트 실패 시 배포 차단, 장애 발생 시 복구
