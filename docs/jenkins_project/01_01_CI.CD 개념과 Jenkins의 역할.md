# Jenkins 프로젝트 학습

## 1장 1교시 — CI/CD 개념과 Jenkins의 역할

### 1. CI/CD란?

CI/CD는 소스 코드의 통합, 빌드, 테스트, 배포 과정을 자동화하여 개발 효율성과 배포 안정성을 높이는 방식이다.

| 구분 | 의미 | 핵심 역할 |
|---|---|---|
| CI | Continuous Integration | 코드 통합 및 자동 빌드·테스트 |
| CD | Continuous Delivery | 언제든 배포 가능한 상태 유지 |
| CD | Continuous Deployment | 검증 통과 후 운영 환경까지 자동 배포 |

### 2. Jenkins란?

Jenkins는 **빌드·테스트·배포 작업을 자동화하는 오픈소스 자동화 서버**이다.

**Jenkins가 필요한 이유**
- 수동 배포의 반복 작업 감소
- 자동 빌드 및 테스트 수행
- 배포 과정의 표준화
- 배포 결과 및 오류 로그 확인
- CI/CD 파이프라인 자동화

### 3. Jenkins CI/CD 동작 흐름

```text
개발자 코드 수정
       ↓
GitHub Push
       ↓
Webhook
       ↓
Jenkins Pipeline
       │
       ├── Checkout : 소스 코드 가져오기
       ├── Build    : JAR 파일 빌드
       ├── Test     : 자동 테스트
       ├── Deploy   : WAS 서버 배포
       └── Verify   : 서비스 정상 확인
       ↓
Spring Boot 서비스 운영
```

※ Build와 Test의 순서는 프로젝트 설정에 따라 달라질 수 있다.

### 4. Pipeline 핵심 구성 요소

| 구성 요소 | 역할 |
|---|---|
| Pipeline | 전체 자동화 작업 흐름 |
| Stage | 개별 작업 단계 |
| Step | 실제 실행할 작업 |
| Jenkinsfile | Pipeline을 코드로 정의하는 파일 |
| `agent none` | 전체 Pipeline에 실행 노드를 할당하지 않음 |
| `echo` | Jenkins 콘솔에 메시지 출력 |

### 5. 장애 대응 핵심

**① 테스트 실패 (배포 전)**
- 신규 버전 배포 차단
- 기존 정상 서비스 유지
- 오류 수정 후 재검증

**② 배포 후 장애 발생**
- 서비스 장애 확인
- 필요시 이전 정상 버전으로 롤백
- 원인 분석 및 재발 방지

**주의:** 자동 배포는 사람의 실수를 줄이지만, 잘못된 설정이나 코드로 인한 장애까지 모두 방지하지는 못한다.

- Console Output 확인

- 객관식 확인문제 8/8 정답

### 7. 핵심 요약

1. **CI = 코드 통합 + 자동 검증**
2. **CD = 배포 준비 또는 자동 배포**
3. **Jenkins = CI/CD 자동화 서버**
4. **Pipeline = 자동화 작업의 실행 흐름**
5. **Jenkinsfile = Pipeline을 코드로 관리**
6. **테스트 실패 = 배포 차단 / 배포 후 장애 = 필요시 롤백**
